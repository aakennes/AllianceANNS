Shuffle 布局导出优化：未来工作（2026-11-18）

状态：已规划，暂不实施。当前 SIFT100M 保持现有 shuffle 和全量验收，
验收通过后优先进行 Mixed 的内存预算与 RaBitQ 1/2/3/4-bit 参数选择。

用户确认的方向
1. 原图按物理页顺序读取一次，同时拆出全部目标级的邻居记录及向量。
2. 各级沿用已计算的 BlockBNF 排序；重叠层按现有布局复制；保留节点 ID、
   邻居顺序、向量、属性及最终布局格式。距离槽不导出。
3. 桶的大块缓冲采用 48 GiB 上界，达到回写阈值后批量写回 SSD。
   工程实现必须在分配下一批之前检查预算，不能先超限再回写。
   总内存还包括排序/逆映射、索引元数据、读缓冲、在途 AIO 缓冲和页组装。
   因此缓冲池实际额度应从 48 GiB 扣除这些固定开销及安全余量；在途缓冲
   直到 I/O 完成才能释放或复用。达到高水位时回写，必要时施加背压。
4. 使用 O_DIRECT + libaio 和对齐的大块缓冲；临时数据仅放 SSD，不放 pmem。

推荐执行流
  校验并保存各级排序 checkpoint
  -> 规划最终页范围、生成 node_id 到目标位置的逆映射
  -> 顺序预取原图连续块（块内拆成节点页）
  -> 每个节点拆分四组邻居和向量记录，追加到按目标页范围划分的桶
  -> 全局桶缓冲达到阈值，选择大块缓冲异步追加到各桶文件
  -> 逐桶顺序读回，在有限内存中按目标位置组装完整页
  -> 连续写出对应最终布局区域
  -> 同步、校验、提交该桶 checkpoint，再删除已消费桶
  -> 全量独立验收、ML-only 加载验收、哈希及 manifest-last 发布

不能把桶缓冲简单等同于最终页缓存：每级独立排序导致同一目标页的节点
分散到达。逐节点散写最终页会引起反复读改写。桶存放带目标位置的记录，
回写应保持大块追加；最后才按完整页组装。多个桶交替追加不等同于全盘
单一顺序流，仍需测量真实设备 I/O、吞吐、RSS 和临时盘峰值。

SIFT100M M48/wp7/d128 估算（不含验收和哈希）
- 原图顺序读一次：381.47 GiB。
- 最终布局：314.71 GiB。
- 临时记录有效内容：309.20 GiB。
- 若五份记录分别增加 8 字节目标键：桶约 312.92 GiB。
- 原图读 + 桶写/读 + 最终布局写：约 1322.03 GiB。
- 四组 uint32 逆映射：约 1.49 GiB；向量复用第一组映射。
- 磁盘规划必须计入旧输出、未消费桶和新输出；不能只计算有效 payload。
  逐桶提交后删除可降低后半程临时峰值，分配前仍要检查完整安全上界。

后续代码职责
- stages/orders：持久化排列、级定义、原图/metadata 身份和配置指纹。
- format/plan：纯页几何、目标位置、桶范围及预算规划。
- export/source_scan：连续 O_DIRECT/libaio 预取和节点解码。
- export/bucket_store：全局有界缓冲、回写/背压、对齐、尾块与错误处理。
- export/page_assemble：逐桶完整页组装，检测重复/缺失/越界槽位。
- stages/export：调度、阶段恢复和进度，不混入排序策略。
- stages/verify：独立读取原图与结果逐字段核对，不以临时桶为正确性证明。
- stages/artifacts：保留可恢复 checkpoint，全部验收后才发布完成清单。

兼容与恢复验收
使用同一排列比较新旧 graph/layout/metadata 的逐字节内容及 SHA；覆盖
小内存、多桶、尾页、4/8/16 KiB 几何、异常短 I/O 和中断恢复。节点、边、
邻居顺序、全部向量及属性必须一致。不得为了导出速度改变排序、搜索或
正确性条件。先完成小规模回归，再做隔离性能对比，不覆盖正式输出。
